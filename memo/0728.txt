통합구현
- 사용자 요구사항을 해결하기 위해 여러 시스템의 기능과 데이터를 연계통합하여 하나의 서비스 환경을 구성하는 과정이며, 송수신 방식, 아키텍처, 모듈 구현 등을 고려하여 시스템 간 데이터 교환과 처리를 수행하는 활동

통합구현이 필요한 이유
1. 이기종 시스템 간 데이터 연계 필요성 증가
- 기업에서는 하나의 프로그램만 사용하는 경우가 거의 없다.
- ERP, 그룹웨어, 홈페이지, 모바일앱, 회계 프로그램이 모두 연결되어야 한다.
ERP(Enterprise Resource Planning) : 회사의 여러 업무를 하나의 시스템에서 통합 관리하는 소프트웨어

2. 서비스 확장성과 재사용성 확보
- 기존 시스템을 그대로 사용하면서 새로운 서비스를 쉽게 추가할 수 있다.

3. 운영 효율성과 데이터 품질 향상
- 같은 데이터를 여러번 입력하지 않아도 된다.
(한번 회원가입하면 다른 시스템들도 정보를 알고 있다)

4. 신규 서비스 창출
- 기존 데이터를 조합하여 새로운 서비를 만들 수 있다.

- 다음 중 통합 구현이 필요한 이유가 아닌 것은? 4
    
    ① 데이터 공유
    ② 서비스 확장
    ③ 운영 효율성 향상
    ④ 프로그램 삭제

목적 : 여러 시스템을 연결하여 데이터를 공유하고 업무를 효율적으로 처리하기 위해 수행한다.

주요 기능
- 데이터 생성 및 송신 : 필요한 데이터를 생성하여 다른 시스템으로 전송
- 데이터 변환 및 매핑 : 데이터 형식을 변경하거나 항목을 연결
- 데이터 수신 및 정제 : 받은 데이터를 검증하고 저장
- 연계 데이터 관리 : 데이터 형식과 저장 방식을 관리
ㄴ JSON, XML, CSV, TEXT
ㄴ 파일, 데이터베이스, 클라우드, 메시지
- 네트워크 및 프로토콜 관리 : 안전하게 데이터를 전송
ㄴ HTTP, HTTPS, FTP, TCP, UDP

연계 요구사항 분석
- 사용자의 요구사항을 분석하여 연계 데이터를 정의하고, 연계 시스템 아키텍처를 설계하기 위한 작업이며, 데이터 발생 패턴, 보안, 성능 등을 분석하여 통합 구현의 설계 기반 자료를 마련하는 과정이다

연계 요구사항을 분석해야 하는 이유
1. 사용자 요구사항을 구체화
- 통합구현을 위한 사용자의 요구사항을 구체화하고 설계에 반영하기 위한 사전 활동
2. 연계 데이터의 형식,범위,주기, 전송방식을 명확히 규정한다
- 연계 데이터의 형식,범위,주기,전송방식을 명확히 규정하여 통합 구현의 설계 품질을 향상시키는데 필요하다
3. 연계 시스템 간 호환성,확장성 확보 및 오류 예방
- 지금 당장은 ERP만 연결하지만 CRM, 모바일, AI까지 시스템이 확장될 수 있다.
- 미리 구조를 잘 설계해야 나중에 확장할 수 있다.
4. 서비스 품질 보장
- 통합 구현의 성능, 보안, 가용성 등 서비스 품질을 보장하는데 필요하다

연계 요구사항 분석 절차
1. 현행 시스템 및 운영환경을 파악
- 하드웨어, 네트워크, 소프트웨어 구성, 어플리케이션 구조, ERD를 확인한다
2. 사용자 요구사항 수집
- 인터뷰, 설문, 체크리스트, FGI를 동해 연계 목적, 범위, 데이터 항목, 발생 주기를 식별한다
3. 연계 데이터 분석
- 데이터 형식,변환, 보안 요구와 연계 솔루션 비교및 검토를 한다.
- 수집한 요구사항을 분석한다.
4. 결과 정리
- 요구사항 분석서, 인터페이스 정의서, 회의록 등을 작성한다

입력물
- 요구사항 분석을 시작하기 전에 준비해야하는 자료

시스템 구성도
- 시스템을 구성하는 하드웨어, 소프트웨어, 네트워크의 연결 구로를 나타낸 문서

응용 어플리케이션 구성도
- 현재 운영중인 프로그램이 어떤 화면과 기능으로 구성되어 있는지 설명한 자료
- 화면 및 프로세스 설계서, 인터페이스 정의서 등이 필요하다

ERD
- 데이터베이스 구조를 그림으로 표현한 문서
- 테이블 속성, 관계, 공통 코드 정의 등이 필요하다

도구 및 기법
사용자 인터뷰 및 FGI(Focus Group Interview)
- 사용자와 직접 대화하여 요구사항을 확인하는 방법
- 핵심 사용자 및 관리자 그룹 면담을 한다
체크리스트
- 성능, 보안, 데이터 발생 주기, 연계 환경, 고려 사항 등을 점검하는 기법
- 빠뜨리지 말아야 할 항목을 미리 정의한 목록
설문조사
- 데이터 항목, 발생 주기, 활용 목적을 확인하는 기법
- 많은 사용자에게 동일한 질문을 하여 요구사항을 수집한다
델파이기법
- 여러 전문가의 의견을 반복적으로 수집하여 하나의 결론을 도출하는 방법
연계 솔루션 비교 분석
- ESB, EAI, OPEN API등 방식별 장단점을 비교하는 기법
ESB(Enterprise Service Bus) : 여러 시스템이 공통 통신 통로인 버스를 통해 메시지와 서비스를 주고받도록 하는 통합 구조
EAI(Enterprise Application Integration) : 기업 내부에서 따로 운영되는 여러 업무 시스템을 서로 연결하여 데이터와 기능을 공유하도록 만드는 통합 방식

출력물
요구사항 분석서
- 식별된 요구사항 정의, 분석 내용, 제약 조건, 종료 조건 등을 포함한다

인터페이스 정의서
- 데이터 항목,형식,전송,방식, 주기 등을 포함한다.

회의록
- 분석과정에서 합의 사항 등을 기록한다
- 회의 일시, 참석자 논의 내용, 결정 사항, 향후 일정을 포함한다.

연계 요구사항 분석하기

1. 요구사항 분석을 의한 정보 수집 및 현황 확인 등 사전작업을 준비한다.
- 송/수신 시스템의 S/W, H/W, N/W구성 현황 확인
ㄴ 어떤 서버에서 운영되는가?
ㄴ 운영 체제는 어떤걸 사용하는가
ㄴ DBMS는 어떤걸 사용하는가
ㄴ WAS는 어떤걸 사용하는가
ㄴ 네트워크는 어떻게 연결되어 있는가
- 송/수신 시스템에서 연계하고자 하는 데이터 관련된 코드 정의서, 테이블 정의서를 확인한다.
ㄴ 테이블 정의서 : 한글 컬럼명, 영문 컬럼명, 타입, 길이, PK 구분, NOT NULL,연관테이블 확인
ㄴ 코드정의서 : 코드 분류, 코드 분류명, 공통 코드, 코드명, 사용여부 확인

2. 사용자 인터뷰 및 면담을 수행하고 회의록을 작성한다.
- 사전에 준비한 시스템 구성도, 테이블 정의서, 코드 정의서, 체크리스트 등을 배포 및 공유하고, 사용자 인터뷰를 진행한다
- 사용자 인터뷰를 완료한 후 인터뷰 시 진행 내용, 확인 사항 등을 회의록에 정리
- 정리된 회의록 내용은 사용자 인터뷰 시의 참석자에게 확인을 받는다

3. 연계 요구사항 분석하기
- 요구사항 분석을 위한 입력물을 파악한다
ㄴ 시스템 구성도 파악하기
ㄴ 응용 어플리케이션 구성도 파악하기
ㄴ 엔티티 관계도, 테이블 정의서 파악하기
- 요구사항 분석 시 도구 및 기법을 활용한다
ㄴ 핵심 사용자와 인터뷰 진행
ㄴ 체크리스트의 활용
ㄴ 설문지 및 설문 조사를 활용한다
ㄴ 델파이 기법을 활용한다
ㄴ 연계 솔루션 비교 분석을 한다

4. 연계 요구사항 분석 결과를 작성한다
- 연계 요구사항 분석서를 작성한다
ㄴ 요구사항 ID별로 요구사항명, 요구사항 유형 및 설명을 포함하여 작성한다.

연계 데이터 표준화 수행

연계 데이터 식별
- 개발하려는 응용 SW의 외부 내부 모듈 간 필요한 데이터를 식별하고, 이를 표준화, 정의하여 연계(인터페이스) 설계에 반영하는 과정을 의미한다.
- 연계 데이터 식별을 위해 연계 범위와 항목을 구체적으로 확인하고, 코드 매핑,변환 변경 구분, 데이터 표현 방식, 인터페이스 정의 등을 식별하여 데이터 교환 표준을 수립하는 데 기반이 되는 활동이다

왜 식별을 해야 하는가?
1. 송수신 시스템 간 데이터 구조,코드 불일치 해소
2. 데이터 송수신 과정에서의 오류 예방 및 품질 확보
3. 효율적인 변환 매핑 검증 절차 수립
4. 데이터 표준화로 향후 확장성,유지보수성 강화
5. 보안, 성능, 데이터 주기 등 서비스 품질 보장

연계 데이터 식별 절차
1. 연계 범위 및 항목 정의
- 연계 대상 시스템 간 데이터 그룹, 단위 항목을 식별하고, 테이블/파일의 구성 항목 및 데이터 타입, 길이, 코드화 여부를 확인한다.

2. 연계 코드 변환 및 매핑
- 송신 코드와 수신 코드 간 매핑 또는 통합 표준코드를 변환한다
- 송/수신 시스템에서 사용하는 코드가 서로 다를 경우 변환 규칙을 정의한다

3. 연계 데이터 식별자(PK) 및 변경 구분 추가
- 연계 데이터에는 어떤 데이터인지 식별할 수 있는 값(PK)과 변경 이력을 함께 관리하는 경우가 많다

4. 연계 데이터 표현 방식 정의
- DB 테이블 형식, 파일 형식 등을 결정한다
- JSON, XML, CSV

5. 연계(인터페이스) 정의서 및 명세서 작성
- 앞에서 분석한 내용을 문서로 정리한다.
ㄴ 인터페이스 ID : 인터페이스 식별 번호
ㄴ 인터페이스명 : 연계 기능 이름
ㄴ 송신 시스템 : 데이터를 내보내는 시스템
ㄴ 수신 시스템 : 데이터를 받는 시스템
ㄴ 데이터 항목 : 전송할 데이터
ㄴ 데이터 길이 : 최대 길이
ㄴ 데이터 타입 : 데이터의 타입
ㄴ 전송 방식
ㄴ 전송 주기

입력물
- 연계 데이터를 식별하기 위해 필요한 자료를 준비한다

현행 시스템 테이블 구조, 파일 구조, 데이터 사전
- 어떤 데이터가 존재하는지 확인할 수 있다.
업무 프로세스 및 데이터 흐름도
- 업무가 어떤 순서로 진행되고 데이터가 어떻게 이동하는지 파악한다
표준 코드 목록 및 공통코드 정의서
- 시스템에서 사용하는 코드 체계를 확인하여 코드 변환이 필요한지 분석한다

도구 및 기법
데이터 매핑 툴, ERD 도구, 표준 코드 관리 시스템
- 송/수신 시스템의 컬럼을 연결하는 데 사용
체크리스트
인터뷰,워크숍을 통한 업무 담당자의 의견 수집
- 업무 담당자와 의견을 공우하여 실제 업무에 필요한 데이터를 확인한다

출력물
연계 데이터 목록 및 표준 정의서
코드매핑표
변경 구분 정의서 및 관리 항목표
연계(인터페이스)정의서 명세서

연계 데이터 표준화
- 송/수신 시스템 간 교환되는 데이터를 식별하고 이를 코드, 형식, 길이, 표현 방식 등의 기준에 맞추어 일관되게 변환 정의하는 과정을 의미하며 연계 데이터 표준화 결과는 연계(인터페이스)정의서로 문서화되어 시스템 설계와 구현에 반영된다
- 시스템마다 컬럼명, 데이터 타입, 코드 체계, 데이터 길이가 다를 수 있다.
- 표준화 하지 않으면 데이터가 정상적으로 전달되지 않거나 오류가 발생할 수 있다.

표준화의 단계
1. 연계 범위 및 항목 정의
2. 코드를 매핑
3. 변경 데이터를 구분
4. 데이터의 표현 방식 정의
5. 인터페이스 정의서 작성

표준화의 필요성
1. 송/수신 시스템 간 데이터 불일치 해소
- 시스템마다 사용하는 데이터 형식과 코드 체계가 다를 수 있다.
- 차이를 미리 표준화 하지 않으면 데이터 누락이나 오류가 발생할 수 있다.
2. 변환 및 매핑 규칙을 명확하게 정의하여 오류 예방
- 송/수신 시스템의 코드가 다를 경우 변환 규칙을 정의한다
- 코드 매핑 규칙을 미리 정의하면 연계 프로그램이 자동으로 데이터를 변환할 수 있다.
3.데이터 품질 보장
- 표준화된 데이터를 사용하면 데이터의 정확성, 일관성, 완전성을 유지할 수 있다.
ㄴ 중복 데이터의 감소
ㄴ 누락 데이터 방지
ㄴ 잘못된 데이터 입력방지

4. 성능 최적화
- 데이터 형식이 미리 표준화되어 있으면 연계 과정에서 불필요한 변환 작업이 줄어든다.
ㄴ 처리 속도 향상
ㄴ 서버 부하 감소
ㄴ 재처리 작업 최소화

5. 유지보수성 향상
- 새로운 시스템이 추가되거나 기존 시스템이 변경되더라도 표준화된 기준을 사용하면 쉽게 연계할 수 있다

6. 보안 및 관리 용이성
- 연계 데이터를 표준화 하면 개인정보 보호나 접근 권한 관리도 일관성 있게 수행할 수 있다
ㄴ 주민등록번호 암호화
ㄴ 개인정보 마스킹
ㄴ 공통 보안 정책 적용

표준화 절차
1. 연계 범위 및 항목 정의
- 어떤 데이터를 연계할 것인지 결정
- 모든 데이터를 연계할 필요는 없고, 필요한 것만 선택하여 연계한다.

2. 코드 매핑 정의
- 송/수신 시스템의 코드 체계가 다를 경우 변환 규칙을 정의한다

3. 변경 데이터 구분 정의
- 연계 데이터가 새로 등록되었는지, 수정되었는지, 삭제되었는지를 구분하는 기준을 정리한다
- 수신 시스템은 변경 구분 값을 보고 어떤 작업을 수행해야 하는지 판단한다.

4. 데이터 표현 방식 정의
- 연계 데이터를 어떤 형식으로 전송할 것인지 결정한다.
- JSON, XML,CSV, DB table

5. 인터페이스 정의서 작성
- 앞에 정의한 내용을 문서로 정리한다
- 개발자와 운영자가 동일한 기준으로 시스템을 구현하기 위한 공식 문서가 된다.

연계 데이터 표준화 수행하기
연계 범위  및 항목을 정의
1. 연계 정보를 상세화 한다.
- 시스템 간에 연계하려는 정보를 상세화하며 범위와 항목을 정의한다.

2. 연계 항목의 데이터 형식을 확인한다.
- 송/수신 시스템에서 연계하고자 하는 항목을 확인한다
ㄴ 길이, 타입, 코드화 여부
- 연계 항목이 송/수신 시스템이 서로 다른 경우 일반적으로 연계 정보가 활용되는 수신 시스템을 기준으로 연계항목을 적용하고 변환한다

연계 코드 변환 및 매핑
1. 연계 코드 변환을 한다
- 범위 및 항목을 식별한 후, 연계 정보 중 코드로 관리되는 항목을 변환한다.
ㄴ 송신 시스템의 코드를 수신 시스템 코드로 매핑하는 방법
ㄴ 송/수신 시스템에서 사용하는 코드를 통합하여 표준화한 후 변환하는 방법

2. 송신 시스템 코드를 수신 시스템 코드로 매핑한다.
- 송신 시스템 코드를 수신 시스템 코드로 매핑할 때 그룹별로 코드 그룹명, 코드명, 등의 항목을 포함한다.

3. 송수신 시스템의 코드를 통합하여 표준화한 후 매핑한다
- 송/수신 시스템의 코드를 통합하여 표준화 한 후 매핑은 표준화 코드, 송신 시스템 코드, 수신 시스템 코드 등의 항목을 포함한다.

연계 데이터 식별자와 변경 구분 추가하기
1. 식별자(PK) 추가하기
- 송신된 정보가 수신 시스템의 어떤 데이터에 해당하는지 확인하기 위해 수신 시스템의 연계 정보에 송신 시스템의 식별자 키 항목을 추가한다

2. 변경 구분 추가하기
- 수신 시스템에 송신 데이터를 반영하기 위해서 송신 정보를 수신 시스템의 테이블에 추가하거나 수정 또는 삭제할 데이터인지 식별해 주는 구분 정보를 추가한다.

3. 관리를 위한 정보를 추가한다
- 연계되는 정보의 송수신 일시, 송수신 여부, 오류 코드 등을 확인하고 모니터링 하기 위해 인터페이스 테이블에 관리 정보를 추가한다.

연계 데이터를 표현한다
- 연계 대상 항목과 코드 매핑 방식 등을 정의한 후, 연계 데이터를 테이블 또는 파일 등의 형식으로 구성한다.
- 연계 데이터는 응용 어플리케이션에서 연계 주기, 연계 데이터를 생성하는 시점, 적용되는 연계 솔루션의 기능에 따라 다르게 표현될 수 있다.
- 연계 데이터는 기본적으로 데이터베이스의 테이블 형식으로 표현한다
- 파일을 사용하는 경우에는 파일 형식에 따라 태그 항목, 분리자 사용 등에 의해 상세화된다.

연계 정의서 작성하기
1. 연계(인터페이스)정의서 작성
- 연계 데이터 타입 및 길이, 연계 항목으로 구성된다.
- 송신 시스템과 수신 시스템 간의 인터페이스 현황을 작성한다

2. 연계 명세서 작성하기
- 정의서에 작성한 인터페이스 ID별로 송수신하는 데이터 타입, 길이 등 인터페이스 항목을 상세하게 작성한다

데이터 정합성 : 서로 관련된 데이터가 모순되지 않고, 정확하게 일치하는 상태
상호 운용성 : 서로 다른 시스템이 데이터를 주고받고, 전달받은 데이터를 올바르게 이해하여 함께 동작할 수 있는 능력

ISO : 국제 표준화 기구(전 세계에서 사용할 공통 규칙을 만드는 국제기구)

UN/EDIFACT(Electronic Data Interchange For Administrain Commerce and Transprot) : 무역과 물류에서 사용하는 국제 전자문서 표준

HL7(Health Level Seven) : 병원 시스템끼리 의료정보를 교환하기 위한 국제표준

연계서버 또는 송신어댑터의 주요 기능
1. 데이터 변환
- 송신 시스템과 수신 시스템의 데이터 형식을 맞춰주는 기능
송신 : JSON , 수신 : XML을 쓸 때 연계서버가 JSON -> XML로 변환
- 데이터 포맷, 필드명, 코드값을 변환한다

2. 프로토콜 변환
- 시스템마다 사용하는 통신 방식을 바꾼다
쇼핑몰 : REST , ERP : FTP를 쓴다 연계 서버가 REST -> FTP로 바꿔준다

3. 메시지 라우팅
- 데이터를 어디로 보낼지 결정하는 기능이다.
쇼핑몰에서 주문이 발생하면 연계 서버가 ERP로 보낸다.
결제 -> 회계, 배송 -> 물류

4. 통합 모니터링 및 로깅
- 모든 송수신 내역을 기록하는 기능
10:00 주문 전송 성공, 10:01 ERP 저장완료, 10:02 물류 전송 실패와 같이 모두 기록한다

5. 보안 기능
- 시스템끼리 데이터를 주고받으므로 보안이 매우 중요하다
데이터 암호화
인증(Authentication) : 누구인지 확인
인가(Authorization) : 권한 확인
접근 제어 : 허가된 시스템만 접속하도록 한다

6. 재처리 기능
- 전송 실패시 재전송, 장애 복구 지원

7. 성능 최적화
- 대용량 데이터 전송 시 병렬 처리, 로드 밸런싱

8. 스케쥴링
- 주기적으로 자동 실행하는 기능(배치)

9. Event Handling
- 이벤트 발생 기반 데이터 송수신
주문 발생 -> 재고 차감 -> 결제 -> 배송 -> SMS -> 메일

연계 서버 또는 송신 어댑터의 용도
1. 이기종 시스템 간 연계 
이기종 시스템 : 서로 다른 기술이나 환경으로 만들어진 시스템
직접 연결하려고 하면 데이터 형식과 통신방법을 알아야 하는데, 시스템이 많아질수록 송신 시스템 안에 변환코드가 계속 추가된다. 이로 인해 시스템 간 의존성이 커지고 유지보수가 어려워진다.

2. 실시간 API 호출 시 프로토콜 변환
- 사용자의 요청이나 업무가 발생했을 때 즉시 다른 시스템을 호출하여 결과를 받는 방식
- 프로토콜이 서로 다를 때 수신시스템쪽에 맞춰서 변경을 해줄 수 있다.

3. 배치 파일 송수신 처리
배치 방식 : 데이터가 발생할 때마다 즉시 전송하지 않고, 일정 시간 동안 데이터를 모았다가 정해진 시간에 한꺼번에 처리하는 방식

4. 대용량 데이터 전송 및 재처리 관리
수십 건 정도의 데이터는 단순하게 전송할 수 있지만, 수십만 건 또는 수백만 건이라면 다음 문제가 발생할 수 있다.
- 처리시간이 길어짐
- 메모리 부족
- 네트워크 과부하
- 전송 도중 연결 끊김
- 일부 데이터만 처리됨
- 같은 데이터가 중복 처리됨
- 실패 지점을 찾기 어려움
재처리 관리
- 전송에 실패한 데이터만 재전송하기

5. 보안이 요구되는 데이터 교환 환경
- 연계 서버는 단순히 데이터를 전달하는 것뿐만 아니라 누가 보내고, 누가 받을 수 있으며, 전달과정에서 데이터가 노출되지 않는지 관리해야 한다.

6. 이벤트 기반 시스템 통합
사건이 발생하면 이벤트를 발행하고, 이를 구독한 여러 시스템이 각각 필요한 작업을 수행하는 방식

7. 클라우드와 온프레미스 간 데이터 연계
온프레미스 : 자체 전산실이나 데이터네선에 직접 설치하여 운영하는 환경
클라우드 : 인터넷을 통해 외부 클라우드 사업자의 서버, 데이터베이스, 저장소 등을 사용하는 환경
- 외부 클라우드 환경과 기업 내부 시스템이 안전하게 데이터를 주고받도록 연결하는 것

연계서버 수신 어댑터의 기능
- 수신 시스템이 실제로 처리할 수 있는 형태로 바꾸고, 올바른 목적지에 안전하게 전달하는 역할

1. 데이터 변환
- 송신시스템에서 받은 데이터를 수신 시스템의 데이터구조와 규칙에 맞게 바꾸는 기능
ㄴ 데이터 포맷 변환 JSON -> XML
ㄴ 필드명 매핑 orderId -> order_id
ㄴ 데이터 타입 변환 : 문자열 -> 숫자

2. 프로토콜 변환
- 송신 시스템과 수신 시스템이 서로 다른 통신 방법을 사용할 때, 중간에서 통신 방식을 변환하는 기능
ㄴ FTP -> HTTP
ㄴ REST -> 데이터베이스

3. 메시지 라우팅
- 수신한 데이터를 분석하여 어느 시스템 또는 어느 처리 기능으로 보낼 것인지 결정하는 기능
ㄴ 메시지 종류 기반 라우팅
ㄴ 조건부 라우팅
ㄴ 콘텐츠 기반 라우팅

4. 오류 처리 및 로깅
- 데이터 수신이나 처리 과정에서 문제가 발생했을 때 오류를 확인하고, 기록하고, 필요하면 재처리할 수 있도록 관리하는 기능
ㄴ 오류 종류별로 코드 생성
ㄴ 로그 기록
ㄴ 재처리 관리
ㄴ 실패 메시지 보관
ㄴ 중복 처리 방지

5. 보안관리
- 수신 데이터가 외부에 노출되거나 위조되지 않도록 보호하고, 허가된 시스템만 접근하도록 관리하는 기능
ㄴ 암호화 복호화
ㄴ 인증
ㄴ 인가와 접근 제어
ㄴ 데이터 무결성 검증
ㄴ 민감정보 마스킹

6. 이벤트 처리
- 어떤 사건이 발생했을 때 이벤트를 수신하고, 그 이벤트에 맞는 업무를 자동으로 실행하는 기능

7. 배치 처리 지원
- 대량의 데이터를 한 건씩 실시간 처리하지 않고 일정한 단위로 모아서 한꺼번에 처리하는 기능

8. 통합 모니터링
- 연계 서버와 수신 어댑터에서 처리되는 모든 연계 상황을 한 화면에서 확인하고 관리하는 기능이다.

연계 서버 수신 어댑터의 용도
1. 수신 시스템 내 I/F Table 생성 밎 데이터 적재
- 시스템 간에 데이터를 주고받기 위해 사용하는 중간 저장용 테이블
- 송신 시스템에서 전달받은 데이터를 수신 시스템의 실제 업무 테이블에 바로 저장하지 않고 먼저 I/F Table에 저장한다.

2. 이기종 시스템 간 포맷,코드 변환
- 서로 다른 데이터 형식, 필드명, 데이터 타입, 코드값을 수신 시스템의 기준에 맞추는 것

3. 실시간 Event 수신 및 처리
- 주문 완료나 결제 완료 같은 사건이 발생했을 때 해당 이벤트를 즉시 수신하여 관련 업무를 실행하는 것

4. API 기반 통합 연계
- 시스템이 제공하는 API를 호출하여 필요한 데이터를 실시간으로 조회,등록,수정하는 방식

5. 클라우드와 온프레미스 연계
- 외부 클라우드 서비스와 기업 내부 시스템이 보안 통신망을 이용해 데이터를 교환하도록 연결하는 것이다.

6. 메시지 기반 비동기 통합
- 송신 시스템이 메시지 큐에 전달한 뒤 처리 완료를 기다리지 않고, 수신 시스템이 나중에 세미지를 가져와 처리하는 방식

내외부 연계모듈 구현하기
연계 요구사항을 분석
연계 데이터 표준화 수행
연계 데이터 추출
코드 매핑 및 데이터 변환
인터페이스 테이블 또는 파일 생성
연계 서버나 송신 어댑터를 이용해서 송신데이터를 인터페이스 테이블이나 파일에 저장을 한다.
전송
연계 서버나 수신 어댑터를 이용해서 인터페이스 테이블이나 파일에 있는 데이터를 운영DB에 저장한다

1. 전송방식
결제 연계 시스템 : 실시간 전송 방식
정산 연계 시스템 : 비실시간(Batch)전송 방식

배치의 장점
대용량 데이터를 시스템 이용률이 낮은 시간대에 일괄 처리함으로써, 운영 시스템의 평소 업무 시간대 트래픽 부하를 대폭 줄이고 안정적인 성능을 유지할 수 있다.

2.
데이터 정합성 보장 : 송/수신 시스템 간의 스키마 및 규격 차이를 완화하여 표준화된 구조로 데이터를 임시 저장 및 가공할 수 있다.

트랜잭션 및 오류 관리 용이 : 전송 과정에서 오류가 발생하더라도 임시 저장 영역의 데이터를 바탕으로 재처리가 쉽고 데이터의 일관성을 유지할 수 있다

전송 주기 차이 완화 : 송신과 수신측의 처리 속도나 주기 차이에 영향을 받지 않고 배치 기반 데이터 적재 처리가 가능하다

3. 코드 매핑 및 데이터 변환
- 송신 시스템에서 사용하는 코드 및 데이터 형식을 수신 시스템이 요구하는 코드 체계, 데이터 타입, 표준 규격에 맞게 변환하는 작업
중앙 집중 매핑 관리의 필요성
상호 운용성 및 데이터 정합성 확보 : 서로 다른 이기종 시스템 간 표준 체계를 준수하여 데이터 오류를 방지하고 정확성을 확보한다
유지보수 용이성 : 향후 코드 체계나 업무 규칙이 변경되더라도 중앙 매핑 영역만 수정하면 되므로 변경사항을 효율적으로 반영할 수 있다

4. 
API 기반 통합 인증 관리 : REST API, Open API 호출 제어와 함께 OAuth2, JWT등을 활용한 통합 인증 및 보안 관리 수행

실시간 이벤트 기반 처리: kafka,메시지 큐등을 활용해 이벤트 발생 시 비동기 실시간으로 데이터를 수집 및 수용한다

분산 트레이싱 : OpenTelemetry,Zipkin 등을 활용해 Trace ID 기반으로 송수신 전체 처리 흐름을 모니터링하고 추적한다

프로토콜 및 데이터 포맷 변환 : 이기종 간 다양한 통신 프로토콜과 메시지 포맷을 수신 시스템에 맞게 즉시 변환

5.
로그의 개념 : 송/수신 시스템 간 데이터 연계 과정에서 발생하는 모든 처리 이력과 결과를 시간순으로 기록,저장한 데이터
목적 : 장애 분석 및 원인 추적, 운영 현황 모니터링, 감사 대응, 재처리 기반 확보

트랜잭션 관리 : 데이터 반영 과정에서 오류 발생 시 처리 전 상태로 롤백한다
오류 데이터 재처리 및 별도 관리 : 실패한 데이터를 별도 오류 테이블/파일로 격리 기록한 후, 원인 수정 후 재전송할 수 있도록 구성한다.
