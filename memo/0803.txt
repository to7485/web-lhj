통합구현
연계 데이터 구성하기

통합구현의 정의
- 서로 다른 시스템이나 모듈을 연결하여 데이터를 주고받고, 하나의 서비스 처럼 작동하도록 만드는 과정
- 사용자의 요구사항을 해결하기 위해 여러 시스템의 기능과 데이터를 연계 통합하여 하나의 서비스 환경을 구성함
- 송수신 방식, 아키텍처, 모듈 구현 등을 고려하여 시스템 간 데이터 교환 및 처리를 수행

통합구현이 필요한 이유
1. 이기종 시스템 간 데이터 연계 필요성 증가
2. 서비스 확장성과 재사용성 확보
3. 운영 효율성과 데이터 품질 향상
4. 싱규 서비스 창출

통합 구현의 주요 기능과 요소
1. 데이터 생성 및 송신
2. 데이터 변환 및 매핑
3. 데이터 수신 및 정제
4. 연계 데이터 관리
5. 네트워크 및 프로토콜 관리

연계 요구사항 분석
- 시스템 연결 전 어떤 데이터를, 어떤 방식으로 주고받을 지 미리 결정하는 사전 작업

요구사항 분석을 해야 하는 이유
1. 사용자 요구사항을 구체화 하기 위해
2. 형식,범위,주기,전송 방식 명확화
3. 확장성 및 오류 예방
4. 서비스 품질 보장

연계 요구사항 분석 절차
1. 현행 시스템 및 운영 환경 파악(하드웨어, 소프트웨어, ERD 등)
2. 사용자 요구사항 수집 (인터뷰, 설문조사, 체크리스트, FGI 등)
3. 연계 데이터 분석
4. 결과 정리 (문서로 작성)

요구사항 분석에 앞서 필요한 입력물
- 시스템 구성도
- 응용 어플리케이션 구성
- ERD

출력물
- 요구사항 분석서 : 요구사항 ID, 유형, 내용, 제약/종료조건
- 인터페이스 정의서 : 연계 데이터 항목, 형식, 전송 방식, 주기 등을 명시
- 회의록 : 참석자, 논의 내용, 결정 사항 및 향우 일정 기록

연계 데이터 표준화

연계 데이터 식별
- 서로 다른 시스템이 데이터를 주고받기 위해 필요한 데이터를 찾아내고, 동일한 기준으로 정의하는 과정

연계 데이터 식별의 필요성
- 단순히 데이터를 전달하는 것을 넘어 데이터의 정확성과 안정적인 교환을 보장하기 위함
- 시스템 간 데이터 불일치 예방
- 코드 체계 불일치 문제 예방
- 데이터 붕복 및 누락 방지
- 개발 생산성 및 유지보수성 향상

연계 데이터 식별 절차
1. 연계 대상 데이터 추출 및 식별
- 송수신시스템간 주고받아야 할 데이터를 테이블 및 컬럼 단위로 추출
2. 연계 데이터 매핑 및 변환 규칙 정의
- 송수신시스템간 항목을 1:1 또는 N:1등의 관계로 연결하고 변환 규칙을 수립
3. 연계 데이터 식별자 정의
- 전송되는 데이터를 유일하게 구분할 수 있는 식별키(PK)또는 Transaction ID 정의
4. 연계 데이터 표준화 수행
- 연계 데이터 용어, 형식, 코드 체계를 공통 기준에 맞춰서 표준화
5. 연계 데이터 명세서 작성
- 식별 및 표준화가 완료된 연계 데이터를 최종 문서로 만들어 체계화


연계 메커니즘 구성하기
- 개발하고자 하는 응용 소프트웨어와 외부 시스템인 연계 대상 모듈 간의 데이터 송수신 요구사항을 충족하고, 데이터 형식, 전송, 보안, 신뢰성을 고려하여 데이터를 안정적이고 효율적으로 교환하기 위한 기술적 체계와 프로세스

연계 메커니즘의 구성 요소
1. 송신 시스템
2. 수신 시스템
3. 인터페이스 테이블 또는 파일
4. 연계 서버 또는 어댑터
5. 로깅 및 모니터링

연계 방식
송/수신 시스템 간 데이터를 교환할 때 정의할 내용
- 사용할 전송 프로토콜
- 사용할 데이터 형식
- 사용할 연계 미들웨어 또는 연계 엔진

연계 데이터 생성 및 추출
- 운영 DB 또는 어플리케이션에서 필요한 데이터를 선별,가공하여 타 시스템으로 송신할 수 있도록 연계 대상 데이터를 생성/추출하는 작업
- 생성/추출 형태 : 인터페이스 테이블, 파일, 메시지

인터페이스 테이블(Interface Table, I/F Table)
- 데이터를 다른 시스템에게 전달하기 위해 별도로 만든 데이터베이스 테이블

물류 시스템은 인터페이스 테이블의 내용을 읽어간다

운영테이블을 직접 읽는다면
- 시스템 속도가 느려질 수 있다
- 잘못 수정될 위험
- 필요한 데이터만 전송하기 어렵다

파일(File)
- 데이터를 텍스트 파일이나 CSV파일, XML 파일 등으로 저장한 후 상대 시스템에게 전달하는 방식
- 파일을 전달하는 방식 : FTP, NAS, 공유폴더
- 구현이 쉽다
- 대량 데이터 전송에 적합
- 다양한 시스템에서 사용 가능
- 실시간 처리가 어렵다
- 파일이 손상될 수 있다
- 중복전송이 될수도 있다

메시지
- 데이터를 네트워크를 통해 실시간으로 전달하는 방식
- 실시간 처리가 가능
- 매우 빠름
- 자동화에 적합
- 대규모 시스템에서 많이 사용
- 구현이 비교적 복잡
- 네트워크 장애에 영향을 받을 수 있음
- 메시지 순서 및 중복 처리를 고려해야 함

연계 데이터 생성/추출시 중요한점
- 데이터 품질 확보
- 성능 최적화
- 운영 안정성
- 보안 및 감사 대응

코드 매핑 및 데이터 변환
- 송신 시스템의 코드, 데이터 타입, 형식을 수신 시스템의 요구 기준에 맞게 변환하는 작업
- 이기종시스템간 호환성 확보
- 데이터 품질과 정확성 홥고
- 표준 준수
- 확장성 및 유지보수 용이성

인터페이스 테이블 또는 파일 생성
- 송/수신 시스템 간 데이터의 연계를 위해 데이터를 임시로 저장하는 중간 영역
- 데이터 저장,가공,변환,검증,송수신을 할 수 있다.
- 데이터 정합성 보장
- 대용량 데이터 처리
- 트랜잭션 관리
- 유지보수 효율성

로그 기록
- 송/수신 시스템 간 데이터 연계 과정에서 발생하는 모든 처리 이력과 결과를 시간순으로 기록하고 저장한 데이터
- 장애 추적 및 분석
ㄴ 송수신 오류, 전송 누락, 데이터 형식 불일치 등의 원인을 파악
- 운영 모니터링
ㄴ 연계 처리 건수, 처리 시간, 처리 결과 실시간 확인
- 감사 및 규제 대응
ㄴ 금융, 공공기관 등의 감사 이력 및 컴플라이언스 요구 대응
- 성능 최적화
ㄴ 병목 구간 분석을 통한 성능 개선 근거 확보
- 재처리 기반 확보
ㄴ 실패 데이터 구분 및 재전송 근거 확보

연계 서버 및 송신 어댑터
- 송수신 시스템 사이에서 중계자 역할을 수행하는 소프트웨어 또는 모듈
- 단순 데이터 전송에서 실시간 API 트래픽 처리, 이벤트 기반 데이터 전달, 보안 관리, 인증/권한 관리, 통합 관제 등의 고도화된 플랫폼으로 발전
주요 기능
- 데이터 변환
- 프로토콜 변환
- 메시지 라우팅
- 통합 모니터링 및 로깅
- 보안 기능
- 재처리 기능
- 성능 최적화
- 스케줄링
- 이벤트 처리

전송
- 송신 시스템에서 생성된 데이터를 네트워크를 통해 수신 시스템으로 전달하는 과정

연계 서버 또는 수신 어댑터
- 수신 측에서 데이터를 받아 이해할 수 있는 형식으로 변환하고 인터페이스 테이블 또는 파일에 적재하는 중재자 엔진
- 데이터 수신 및 변환
- 프로토콜 변환
- 메시지 라우팅
- 오류 처리 및 로깅
- 보안 관리
- 이벤트 처리 및 배치 처리 지원
- 수신 시스템 내 인터페이스 테이블 적재
- API 기반 통합 및 클라우드-온프레미스 연계

최신 기술 동향
- Event-driven Integration(이벤트-기반 통합) : Kafka, Pulsar등을 통한 실시간 데이터 흐름 구축
- Cloud iPaaS : Dell Boomi, SnapLogic 등 데이터 매핑 기반 SaaS 연계 플랫폼 활용
- API Gateway 기반 통합 : Kong, Apigee, Nginx 등을 통한 Api Proxy, JWT/OAuth2 인증 통합 관리
- 분산 트레이싱 : Open Telemetry, Jaeger, Zipkin 기반 Trac ID 활용 송수신 추적
- 보안 강화 : Zero Trust 아키텍처 기반 Field-level Encryption 및 Cloud KMS 활용

운영 DB에 연계 데이터 반영
- 수신된 연계 데이터를 운영 DB 스키마의 업무 규칙에 맞게 변환하여 저장/갱신하는 연계 프로젝트의 최종 단계
- 데이터 정합성 확보
- 업무 연속성 유지
- 데이터 품질 보증
- 규제 및 감사 대응

주요 기능
- 운영 DB에 반영 : 인터페이스 테이블 또는 파일의 데이터를 실제 업무 테이블에 저장 갱신
- 데이터 검증 및 무결성 확인 : 데이터 형식, 코드 체계, 업무 규칙 검증
- 신규/수정/삭제 처리 : Insert, Update, Delete 구분 정보 기반 반영
- 트랜잭션 관리 : 오류 발생 시 Rollback을 통한 일관성 유지
- 처리 결과 기록 및 모니터링 : 처리 결과를 로그로 남겨 상태 모니터링
- 오류 데이터 재처리 : 실패 데이터 별도 관리 및 수정 후 재처리 지원

연계 오류 처리방안

연계 오류
- 서로 다른 시스템 간 데이터를 교환하는 과정에서 데이터가 정상적으로 전송,수신,정상,처리되지 못하고 예외나 문제가 발생하는 사태
오류가 발생 할 수 있는 위치
- 송신 시스템
- 연계 서버
- 수신 시스템
- 파일
- 인터페이스 테이블

연계 오류의 유형
- 연계 시스템 오류 : 인터넷 선이 끊기거나 서버 컴퓨터가 꺼진 경우
- 연계 프로그램 오류 : 데이터 변환 프로그램에 버그가 있는 경우
- 연계 데이터 오류 : 필수 정보인 '이름'이나 '전화번호'가 빈칸으로 온 경우

장애 및 오류 로그
- 시스템이나 프로그램에서 처리 중 발생한 장애나 오류 상황을 기록한 데이터
- 어떤 시점에, 어떤 이유로, 어떤 오류가 , 어떤 데이터에 발생했는지 기록

장애 및 오류 로그의 중요성
- 오류 식별 : 로그를 통해 장애 발생 원인을 규명할 수 있다
- 문제 해결 시간 단축 : 로그 분석으로 장애 원인을 빠르게 찾아 즉시 조치할 수 있다
- 데이터 신뢰성 확보 : 장애 발생 구간과 영향을 명확하게 파악하여 데이터의 정합성을 유지할 수 있다
- 시스템 안정성 확보 : 오류 패턴을 추적할 수 있어 장애를 사전에 예방할 수 있다
- 감사 및 법적 요구 대응 : 장애 이력 관리가 필요한 경우 근거 자료로 활용할 수 있다

활용방안
- 모니터링 화면에 연계
- 분석 자료로 활용 : 시스템 로그와 인터페이스 로그를 통합하여 조회하거나 장애 여부를 실시간으로 확인할 수 있다
- 조치 이력 관리 : 장애 유형에 대한 통계를 추출하거나 재발 방지 대책을 수립할 수 있다
- 자동화 연계 : 언제, 어떤 장애가 발생하였고 어떤 조치를 수행하였는지 파악할 수 있다

장애 및 오류 분석 설계
- 시스템 정상 운영을 방해하거나 데이터 정합성을 훼손하는 오류,예외, 실패 상황을 정의하고, 이러한 상황을 탐지,기록,분석,대응하기위한 로그체계, 코드 설계, 데이터 저장 구조를 체계적으로 정립하는 활동

분석 및 설계 절차
1. 모니터링 화면에서 1차로 확인
2. 로그 및 메타데이터 심층 분석 (2차 확인)
3. 장애 구분, 코드 분류
4. 장애 원인 분석
5. 대응 및 재처리 여부 결정
6. 이력 기록 및 리포트 작성

장애 및 오류 로그의 유형
1. 기록 단위 기준
- 시스템 로그 : 연계 서버 자체의 실행,접속,전송 상태 등 시스템 기능 전반 기록
- 연계 로그 : 송수신 데이터 단위의 전송 변환 처리 등 오류 기록
- 데이터 로그 : 개별 행, 데이터 필드 단위로 상세 오류 기록

2. 영향 범위 기준
- 시스템 전체 : 연계 서버 전체에 해당하는 장애, 오류
- 시스템 일부 : 일부 모듈, 특정 인터페이스, 특정 테이블만 해당하는 오류

장애 및 오류 로그 파일 유형
- 시스템 로그 :  시스템 전체 또는 일부
- 연계 로그 : 연계 인터페이스 단위
- 데이터 로그 : Row(행)단위 또는 데이터 파일 단위

연계 데이터 보안
- 서로 다른 시스템이 데이터를 주고받는 과정에서 무단 접근, 탈취, 변조, 위조 등을 방지하기 위한 활동

전송 구간에 대한 보안
데이터 자체에 대한 보안

보안이 필요한 이유
- 개인정보보호법 등 법,규제 준수
- 해킹과 내부자 유출 방지
- 중간자 공격 방지
- 데이터 무결성 확보
- 서비스 신뢰도 유지
- 클라우드 MSA 환경 보호
- Zero trust 대응

전송 구간 보안
데이터가 네트워크를 통해 이동하는 동안 내용을 가로채거나 변경하지 못하도록 보호하는 것

중간자 공격 방지
- 공격자가 송신자와 수산자 사이에 껴서 데이터를 가로채거나 변경하는 공격
- 아이디 비밀번호 탈취
- 주문 금액 변경
- 계좌번호 변경
- 개인정보 탈취
- 인증 토큰 탈취

HTTPS와 TLS를 사용하면 데이터가 암호화되어 공격자가 내용을 확인하기 어렵다

패킷 스니핑 방지
- 네트워크를 지나가는 데이터를 수집하여 확인하는 행위
- 암호화 하지 않은 통신에서는 아이디, 비밀번호, 주민등록번호, 전화번호, 이메일, 카드정보같은 정보가 노출될 수 있다.

TLS, HTTPS
TLS : 인터넷에서 가장 널리 사용하는 전송 구간 암호화 기술
- 웹사이트, REST API, 모바일 앱, 인터넷 뱅킹, 쇼핑몰 결제
- 널리 지원됨, 구현이 비교적 쉬움, 데이터 도청 방지, 서버 인증 가능

클라우드 API 환경에서 필수
- 최근 대부분의 시스템은 하나의 서버에서만 사용하는 것이 아니라 여러 시스템이 API를 통해 서로 데이터를 주고받는다.
- 전송구간이 보호되지 않으면 고객 개인정보 유출, API 인증 토큰의 탈취, 결제 데이터 변조, 중요 기업 정보 유출, 악성 요청이 발생할 수 있다.
- 그래서 대부분의 클라우드 서비스와 API는 보안기술을 기본적으로 요구한다
- HTTPS, OAuth2, JWT, Mutual TLS, VPN, 전용망

데이터 보안
- 데이터 자체를 암호화하거나 무결성을 보장하여, 저장 중이거나 이동 중에도 노출, 유출, 변조를 방지하는 것을 의미한다
- 연계 데이터는 송신 시스템의 운영 DB에서 추출되어 연계 솔루션을 통해 전송되기 전, 그리고 수신 시스템에서 인터페이스 테이블 또는 파일을 운영 DB에 반영하기 전 단계에서 암호화 및 복호화 처리가 필요하다

데이터 보안의 필요성
- 데이터가 유출되더라도 해독 불가
ㄴ 시스템이 해킹되거나 저장 장치가 분실되면 데이터가 외부로 유출될 수 있다
ㄴ 이때 데이터를 암호화하지 않았다면 공격자는 유출된 파일이나 데이터베이스 내용을 즉시 확인할 수 있다
- 개인정보,금융정보 규제 대응
ㄴ 개인정보나 금융정보는 매우 민감한 데이터이기 때문에 관련 법률과 규정에서는 이를 안전하게 저장하고 관리하도록 요구한다
- 클라우드 환경에서 데이터 안전 확보
ㄴ 데이터가 회사 내부 서버가 아닌 외부 클라우드 사업자의 서버에 저장될 수 있다
ㄴ 클라우드는 편리하지만 데이터가 외부 인프라에 저장되기 때문에 여러 위험이 존재한다
잘못된 접근 권한 설정
다른 사용자의 데이터 접근 가능성
관리자 계정 탈취
클라우드 계정 해킹
저장소 공개 설정 오류
백업 데이터 유출
내부 관리자에 의한 정보 노출

암호화와 복호화
암호화
- 사람이 읽을 수 있는 평문을 알아볼 수 없는 암호문으로 변환하는 과정이다
평문 + 암호화 알고리즘 + 비밀키 -> 암호문
ㄴ 비밀키가 노출되면 암호화된 데이터를 복호화 할 수 있다
복호화
- 암호문을 원래 평문으로 복원하는 과정
암호문 + 복호화 알고리즘 + 비밀키 -> 평문
ㄴ 복호화는 일반적으로 권한이 있는 사용자나 시스템만 수행할 수 있어야 한다

비밀키
- 암호화와 복호화에 사용하는 비밀 값
- 같은 알고리즘을 사용하더라도 어떤 키를 사용하느냐에 따라 생성되는 암호문이 달라질 수 있다.
- 키는 일반적으로 문자,숫자 또는 이진데이터로 구성된다.
키의 역할
- 데이터를 암호화한다
- 암호문을 복호화한다
- 암호화된 데이터에 접근할 수 있는 사용자를 구분한다
- 데이터 보호 수준을 결정한다

키의관리
- 암호화된 데이터와 복호와 키를 같은 위치에 보관하면 공격자가 둘을 함께 탈취할 수 있다
- 키를 별도의 키 관리 시스템에 저장
- 소스 코드에 키를 직접 작성하지 않는다
- 환경 변수 또는 보안 저장소 사용
- 키 접근 권한 제한
- 키를 주기적으로 변경
- 키 사용 기록 저장
- 오래된 키 폐기

암호화 복호화의 필요성
- 데이터 탈취 무력화
ㄴ 공격자가 데이터를 훔쳐가더라도 내용을 해석하거나 활용하지 못하게 만드는 것을 의미한다
ㄴ 암호화되지 않은 데이터는 유출되는 즉시 공격자가 사용할 수 있다

DB내 데이터 노출 차단
- 데이터베이스에는 개인정보, 금융정보, 인증정보 등 중요한 데이터가 저장된다
- 데이터베이스 접근 권한이 잘못 설정되거나 관리자 계정이 탈취되면 저장 데이터가 노출될 수 있다.

데이터 위변조 방지
- 데이터의 변경 여부를 확인하려면 해시, 메시지 인증 코드, 전자 서명 등의 기술을 함께 사용해야 한다.

규제 준수
- 기업과 기관은 개인정보, 금융정보, 의료정보 등 중요 데이터를 법률과 보안 기준에 따라 보호해야 한다
- 중요 데이터 암호화
- 접근 권한 최소화
- 사용자 인증
- 접속 기록 저장
- 데이터 백업
- 키 안전 관리
- 개인정보 마스킹
- 보유 기간이 지난 데이터 삭제
- 유출 사고 대응 절차마련

연계 데이터 보안 적용하기
전송 구간 보안 방식을 결정한다
1. TLS(HTTPS)
2. Mutual TLS
3. SSH(Secure SHell)

송수신간 물리적 방 분리 방식을 결정한다
- 물리적으로 네트워크를 분리하는 방법
- 은행, 국방, 군사, 정부기관
- 해킹 위험 수준이 매우 낮다
- 보안 수준 최고
- 구축 비용이 매우 비싸다
- 유지보수가 어렵다
- 확장성이 떨어진다

VPN(Virtual Private Network 가상사설망) 보안 방식을 결정한다
- 인터넷 위에 전용 통신망을 만드는 기술
- 실제로는 인터넷을 사용하지만 암호화된 터널을 만들어 안전하게 통신한다
- 재택근무, 클라우드에서 많이 사용한다
- 구축비용이 저렴하고 인터넷만 있으면 사용이 가능하다
- 인터넷 품질 영향을 받는다

데이터 보안 방식 파악하기
1. 데이터 암호화 대상을 식별한다

- 암호화 키
- 암호화 복호화 라이브러리

- 암호화 프로세스
ㄴ 암호화 대상 데이터를 파악한다
ㄴ 암호화 알고리즘을 선정한다
ㄴ 암호화 Key를 관리한다 : key vault, HSM
ㄴ 암호화 라이브러리를 적용한다
ㄴ 암호문을 저장한다
- 복호화 프로세스
ㄴ 암호화 KEY 확인
ㄴ 암호문 로드
ㄴ 복호화 수행
ㄴ 평문 사용

4. 암호화 복호화 알고리즘 방식 파악하기
- 대칭키 암호화 : 하나의 키로 암호화와 복호화를 수행
- 비대칭키 암호화 : 공개키로 암호화를 하고 개인키로 복호화를 수행한다

5. 연계 데이터 암호화 방식을 위한 결정 사항을 파악한다
- 어떤 데이터를 암호화 할 것인가?
- 어떤 알고리즘을 사용할 것인가?
- 키는 어떻게 관리할 것인가?
- 어느 구간에서 암호화 할 것인가?

6. 암호화 대상 속성의 데이터 길이를 수정한다
- 암호화 하면 데이터 길이가 증가할 수 있기 때문이다

7. 암호화 알고리즘 라이브러리를 확보하여 설치한다

서버리스 컴퓨팅
서버리스 : 개발자가 서버를 직접 설치하거나 관리하지 않고 어플리케이션만 개발하면, 클라우드 서비스 업체가 서버 운영을 대신 해주는 컴퓨팅 방식
- 실행될 때만 비용 발생
- 필요한 만큼 자동 확장이 된다.
- 콜드 스타트(cold start) : 오랫동안 실행되지 않은 함수는 첫 실행 시 초기화 때문에 응답이 다소 느릴 수 있다.
