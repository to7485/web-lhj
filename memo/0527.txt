데이터 입출력 구현 능력단위
논리 데이터저장소 확인하기
- 엔티티, 속성, 관계가 잘 설정 됐는지
- E-R 다이어그램 잘 그렸는지
- 정규화 잘 됐는지(1~5차, 함수적 종속성, 이상현상)
논리 데이터모델 검증하기
- 필요한 데이터가 빠지지 않았는지(입력, 출력, 연계 데이터)
- 현재 시스템의 데이터구조를 파악했는지(기본 DB구조, 백업, 공통코드, 외부 연계 데이터)
- 사용자 요구사항이 반영되었는가
- 데이터 흐름이 명확한가
- 데이터 모델이 적절한가
- 접근권한과 통제가 명확한가

물리 데이터저장소 설계하기
- 논리 데이터저장소 설계를 바탕으로 목표 시스템의 데이터 특성을 반영하여 최적화된 물리 데이터저장소 설계

반정규화
- 정규화를 조금 포기하고, SELECT 성능을 높이기 위해 데이터의 중복을 감수하고, 테이블 구조를 바꾸는 설계 방법

반정규화를 하는 이유
- 테이블이 너무 잘게 쪼개져있어서 JOIN을 너무 많이해야해서 
- 데이터가 적을때는 괜찮은데 데이터가 많아지면 SELECT 속도가 느려진다.
- 자주 조회하는 데이터를 일부러 합치거나 중복해서 저장한다.

핵심개념
- JOIN을 줄여 빠르게 조회속도 향상
- 합계, 평균을 미리 저장하여 계산 비용 감소
- 자주쓰는 속성은 테이블로 따로 만들어 분리
- 항상 같이 쓰는 테이블을 하나로 합친다.

- 그래서 중복 테이블을 하나 추가한다.

create table order_summary(
	order_id INT primary key,
	customer_name varchar(50),
	product_name varchar(100),
	price int,
	order_date date
)

INSERT INTO order_summary 
SELECT
    o.order_id,
    c.customer_name,
    p.product_name,
    p.price,
    o.order_date
FROM orders o
JOIN customers c
ON o.customer_id = c.customer_id
JOIN products p
ON o.product_id = p.product_id;

특정 부분만 포함하는 테이블 추가
- 큰 테이블에서 자주 사용하는 일부 컬럼만 따로 빼서 테이블을 만드는 방법

테이블 조합
- 항상 같이 사용되는 두 개 이상의 테이블을 하나로 합치는 것

테이블 분할
- 하나의 테이블을 여러개로 나누는 것

수직 분할
- 컬럼별로 사용 빈도의 차이가 많이 나는 경우 자주 사용되는 컬럼들과 그렇지 않은 컬럼으로 분류하여 테이블을 분할하는 방법
- 자주 쓰는 컬럼만 빠르게 조회
- 이미지, 긴 글 같은 무거운 데이터가 있을 때
- 개인정보 접근 권한을 분리해야 할 때

수평 분할
- 특정 범위별 사용 빈도의 차이가 많은 경우 해당 범위별로 테이블을 분할하는 방법
- 행을 기준으로 테이블을 나누는 것

년도별로 테이블을 새로 만듦

CREATE TABLE ORDERS_2024(
	order_id INT PRIMARY KEY,
	customer_name	VARCHAR(100),
	price	INT,
	order_date DATE
)

INSERT INTO ORDERS_2024
SELECT *
FROM orders
WHERE order_date  BETWEEN '2024-01-01' AND '2024-12-31';

UPDATE customer c
JOIN customer_address a
on c.customer_id = a.customer_id
SET c.address = a.address;

컬럼 중복
- 필요한 해당 테이블이나 컬럼을 중복하여 추가한다.
- 다른 테이블에 있는 컬럼을 현재 테이블에도 추가로 저장하는 것이다.
