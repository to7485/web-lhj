1 
연계 오류의 유형 : 연계 데이터 오류
오류의 원인 : 수신 시스템의 운영 DB에 이미 존재하는 회원의 식별키(PK)를 송신 시스템에서 신규 등록하려고 시도하여 발생
해결방안 :  
- 수신 시스템 반영 로직을 기존 회원 존재 여부에 따라 수정/신규로 분기 처리
- 송신 전 데이터 중복 검증 로직 추가하기
해결 후 확인해야 하는 사항 2가지:
- 로그 확인 : 수신 시스템의 처리 로그에서 정상 처리 메시지 및 에러 재발 여부 확인
- 운영 DB 정합성 확인 : CRM DB 내 해당 회원 정보가 누락이나 중복 없이 정확하게 반영되었는지 조회하여 데이터 검증

2.
오류 유형 : 프로그램 오류 ( 데이터 변환 / 매핑 로직 오류)
오류 원인 : 연계 서버의 데이터 변환 프로그램 파서가 JSON 데이터를 XML 규격으로 정상 변환하지 못하거나, JSON 구문 오류로 인해 변환 실패
해결 방안:
- 연계 서버/어댑터의 데이터 변환 모듈을 점검하여, JSON-to-XML 매핑 규칙 및 파서 구성을 수정
적용해야 하는 작업 : JSON -> XML 데이터 포맷 매핑 규칙 적용 및 데이터 변환 프로그램 수정
해결 여부 확인 방법 : 변환 로그를 통해 JSON -> XML 변환 성공 처리 이력을 확인하고, 물류 시스템 DB/인터페이스 테이블에 데이터가 정상 적재되었는지 확인

3.
오류가 발생한 이유 : 데이터 오류(또는 코드 불일치 오류) - ERP와 CRM 간 존재하는 코드 체계가 달라 수신 시스템이 해당 코드를 인식하지 못해 매핑 실패
해결방법 : 연계 서버 또는 수신 어댑터의 코드매핑 테이블에 ERP의 SUPER 코드를 CRM의 ADMIN 코드로 1:1 변환되도록 등록/수정
동일한 문제가 다시 발생하지 않도록 예방 관리 방법 2가지:
- 표준 코드 통합 관리 체계 구축 : 시스템간 표준 코드를 정의하고 중앙 집중식 매핑 테이블 운영
- 코드 변경시 사전 검증 프로세스 수립 : 코드 신규 등록/변경 시 연계 프로그램과 매핑 여부를 사전에 검증

4. 
오류식별 방법 : 연계 서버 및 수신 시스템 로그에서 오류코드와 메시지를 확인
오류 원인 분석 방법 : 송신 시스템의 PK 생성 규칙과 수신 시스템 DB의 기존 PK값을 비교 분석하여 데이터 중복 로직의 결함 여부 확인
해결방안 :
- PK 자동생성 로직을 수정하여 중복 방지
- 수신 데이터 적재 시 기존 데이터가 있을 경우 Insert가 아닌 Update 처리로 분기 로직 적용
해결 여부 확인 방법 :
- 연계 재시도 후 로그에서 pk 중복에러가 사라졌는지 확인하고, 진료 시스템 운영 db에 예약 데이터가 정상 적재되었는지 확인
추적 관리 문서에 기록해야 하는 항목 4가지:
- 오류 발생 일시 및 코드
- 오류 발생 원인 및 대상 데이터
- 조치 내용 및 해결 방안
- 조치자 및 조치 완료 일시

5.
오류 유형 : 연계 시스템 오류(네트워크/보안 환경 오류)
오류 원인 : 방화벽 정책 변경으로 인해 연계 통신용 포트가 차단되어 CRM 시스템으로의 데이터 전송 트래픽이 거부됨
해결 방안 : 네트워크/보안 관리자에게 연계 서버 및 수싵 시스템간 IP/PORT 방화벽 정책 예외 등록 요청
해결 후 확인해야하는 사항 3가지:
- 네트워크 포트 연결성 확인 : Telnet 또는 Ping을 통한 IP/PORT 통신 정상 여부 점검
- 로그 확인 : 연계 서버 및 송신 어댑터의 전송 성공 로그 확인
- 미전송 데이터 재처리 : 차단 기간 동안 누락된 대기 데이터를 재전송하여 CRM 반영 완료 여부 확인
동일한 문제가 다시 발생하지 않도록 예방 관리 방법 2가지:
- 네트워크/보안 정책 변경 전 연계 영향도 사전 검토 : 방화벽 정책 변경 시 연계 포트 포함 여부를 사전 검증하는 절차 마련
- 실시간 모니터링 및 알람 체계 구축 : 포트 차단이나 네트워크 장애 발생 시 즉시 담당자에게 알림이 가도록 관제 설정

연계 오류
- 서로 다른 시스템 간 데이터를 주고받는 연계 과정에서 데이터가 정상적으로 전송,수신,저장,처리되지 못해 발생하는 장애나 오류현상

연계 오류의 세가지 유형
- 연계 시스템 오류 : 인터넷이 끊기거나, 연계 서버/수신 서버 컴퓨터가 꺼진 경우, 방화벽 포트 차단 등 네트워크 및 하드웨어/환경적 장애
- 연계 프로그램 오류 : 데이터 변환/매핑 프로그램의 버그, 파싱 실패, 연계 어댑터 프로그램 실행 오류 등 소프트웨어 로직 결함
- 연계 데이터 오류 : PK 중복, 필수 값 누락, 코드 불일치, 데이터 타입 불일치 등 데이터 자체의 정합성/무결성 결함

연계 오류 식별 방법
로그 파일 조회 : 연계 서버, 송수신 어댑터, db 등의 로그 파일을 확인하여 오류 메시지 및 오류 코드 식별
모니터링 시스템/관제 도구 활용 : 연계 모니터링 화면에서 미처리/실패 건 발생 알림 및 상태 값 확인
인터페이스테이블 조회 : 처리 상태 컬럼 조건을 통한 오류 건 검색

연계 오류 원인 분석 방법
오류 코드 및 메시지 해석 : 에러코드와 예외 추적 내역 분석
송/수신 데이터 비교 : 송신 전 데이터와 수신 수 변환/적재된 데이터 간 필드값,규격,코드값 차이 검증
통신/네트워크 연결성 점검 : Telnet, Ping, Curl명령어로 IP/Port 차단 여부 확인

연계 오류 처리 및 재처리 방안
연계 오류 처리 절차
1. 오류 감지/인터셉트 : 시스템 이벤트, 모니터링 열람, 로그 모듈을 통해 에러 발생 즉시 감지
2. 오류 원인 규명:
- 데이터 오류 : 송신 데이터 보정 및 수신 DB 분기 로직(INSERT/UPDATE) 수정
- 프로그램 오류 : 변환/매핑 로직 수정 및 파서 업데이트
- 시스템 오류 : 네트워크 포트 오픈 및 재전송/재적재
3. 재처리 수행 : 실패한 건에 대한 재전송/재적재
4. 해결 여부 검증 및 이력관리 : 모니터링 및 DB조회로 최종 성공 확인 후 추적 관리 문서 작성
5. 재처리 실행 방식
- 자동 재처리 : 네트워크 순간 지연이나 서버 일시 부하 시 연계 엔진이 일정 간격으로 자동 재시도
- 수동 재처리 : 데이터 수정, 코드 매핑 등록, 방화벽 오픈 등 원인 해결 조치가 완료된 후 관리자 관제 화면에서 [재처리/재시동]실행
6. 연계 오류 추적 관리 및 예방 관리
- 오류 추적 관리 및 문서 작성 항목
ㄴ 인터페이스 ID 및 연계명
ㄴ 오류 발생 일시 및 오류코드/메시지
ㄴ 오류 발생 원인 및 대상 데이터 정보
ㄴ 조치 내용, 조치가, 조치 완료 일시
ㄴ 재처리 실행 여부 및 최종 처리 결과
- 동일 문제 재발 방지 예방 관리 방안
ㄴ 표준 코드 체계 구축 및 중앙 매핑 관리 : 시스템 간 코드 일원화 및 매핑 테이블 관리
ㄴ 사전 데이터 검증 강화 : 송신 전 필수값, 타입, PK 중복 여부를 체크하는 유효성 검증 로직 추가
ㄴ 네트워크/보안 정책 변경 사전 검토 : 방화벽 변경 전 연계 IP/Port 영향을 검증하는 프로세스 수립
ㄴ 실시간 관제 알림 체계 강화 : 장애 발생 즉시 담당자에게 알림이 발송되도록 구성

1.
보안 위협 명칭 : 중간자 공격(MITM : Man-in-The-Middle) 및 패킷 스니핑
원인 : 송수신간 암호화되지 않은 HTTP를 사용함으로써, 공공 wi-fi와 같은 오픈 네트워크에서 공격자가 패킷 분석 도구를 통해 통신 데이터를 가로채 데이터를 조회하거나 주문금액,계좌번호 등을 임의로 수정 할 수 있었기 때문이다
해결책 : https전송 구간 암호화 적용,  송수신 시스템 간 통신 채널 자체를 암호화하여 패킷을 캡처하더라도 알아볼 수 없는 암호문 형태로 전달되게 함으로써 도청 및 변조를 차단한다

2.
탈취 무력화 : 데이터베이스 내 민감 정보가 암호화되어 저장되어 있으면, 공격자가 db 테이블 전체를 탈취하더라도 복호화 키를 소지하지 않는 한 원래의 평문을 해독하거나 악용할 수 없기 때문이다.
즉, 데이터의 물리적 유출 사고가 발생하더라도 실제 정보 노출 피해를 차단할 수 있다.

선택적 암호화의 이유 : 모든 데이터를 암호화하면 데이터 조회, 검색, 정렬 시 복호화 연산으로 인해 시스템 선능이 크게 저하되고, 운영상 불편함이 발생한다.
따라서 법적 규제 대상이거나 민감도가 높은 고유식별정보/금융정보 위주로 암호화하고, 자주 검색되는 정보는 접근 제어나 마스킹 등을 조합해 성능과 보안의 균형을 맞춘다.

3.
문제점 : 소스 코드가 유출될 경우 하드코딩된 암호화 키도 함께 노출되어, 공격자가 db나 전송 데이터를 탈취했을 때 해당 키로 즉시 복호화 할 수 있어 암호화의 보호 효과가 무력화된다.
안전한 키 관리 방안:
- 별도의 전문 키 관리시스템(KMS)활용
- 서버 환경변수 또는 보안 저장소 이용
- 키 접근 권한 최소화 및 주기적인 키 변경 정책 적용

4.
암호화는 데이터 내용을 타인이 읽기 못하도록 숨기는 기밀성을 확보하는 기술이며, 내용이 원본 그대로 유지되었음을 보장하는 무결성과는 차이가 있다.
따라서 암호화만으로는 데이터의 일부가 위변조되었는지 검증하기 어렵다
무결성 검증 기술:
- 해시 함수 : 원본 데이터로 해시값을 생성한 후, 수신측에서 다시 계산한 해시값과 비교하여 일치 여부로 변조를 검증한다
- HMAC/전자서명 : 비밀키나 공인인증서를 이용해 데이터에 서명/인증 코드를 첨부함으로써 무결성 검증과 동시에 송신자의 신원확인까지 수행한다.

5.
연계 데이터 보안의 기본 개념 : 서로 다른 시스템간 데이터를 송수신하는 과정에서 무단 접근, 탈취, 변조, 위변조 등을 방지하기 위해 전송 구간과 저장 구간에 암호화 및 보호기술을 적용하는 모든 보안 활동

MSA 및 클라우드 환경에서 서비스간 연계 데이터 보안을 강화하기 위해 적용할 수 있는 대표적인 기술
mTLS : 기존 TLS가 클라이언트만 서버를 검증했다면, mTLS는 통신하는 두 서비스가 서로의 디지털 서명/인증서를 상호 검증한다. MSA 환경 내 내부 네트워크 구간이라도 Zero Trust 보안 모델을 구현하여, 인가된 마이크로서비스 간의 통신만 허용하고 구간 내 데이터를 암호화한다.
OAuth2 및 JWT : 서비스 간 API 통신 시 사용자/서비스의 자격 증명을 매번 DB에서 확인하지 않고, 전달받은 JWT의 서명을 검증하여 빠르게 접근 원한을 확인한다. API 토큰 탈취 및 무단 API 위초 호출을 차단하기 위해 필수적으로 적용된다.

연계데이터 보안 적용하기
1. 전송 구간 보안 방식 결정
1-1. 전송 구간 암호화 방식을 결정
- TLS(HTTPS) : TLS(Transprot Layer Security)는 인터넷에서 가장 많이 사용하는 전송 구간 암호화 기술
ㄴ 웹 서비스 표준
ㄴ REST API 통신 표준
ㄴ 브라우저와 서버간 암호화
ㄴ 가장 많이 사용하는 방식
장점
- 구현이 쉽다
- 대부분의 웹 서비스에서 사용한다
- 데이터 도청을 방지한다
단점
- 서버만 인증한다
- 서버간 통신에서는 보안이 부족할 수 있다

- mTLS(Mutual TLS) : 양쪽 모두가 서로를 인증하는 방식
장점
- 보안 수준이 매우 높다
- 위조 서버 접속 방지

암호화 알고리즘
SEED
- 1999년 한국인터넷진흥원(KISA)과 국내 암호학자들이 자체 개발한 128비트 대칭키 블록 암호 알고리즘
- 개발 배경 : 미국 중심의 암호 기술 수입 의존도를 낮추고 국내 전자상거래 및 인터넷금융의 보안을 강화하기 위해 국산 표준으로 개발되었다.
- 주요 특징
블록 크기 : 128비트(16바이트)
키 길이 : 128비트, 256비트
구조 : 파이스텔 구조 기반
규격 : 대한민국 국가 표준
ARIA
- 2004년 국가정보원과 산학연 전문가들이 개발한 국가 표준 대칭키 블록 암호화 알고리즘
- 개발배경 : 기존 SEED 알고리즘이 경량 환경이나 경량 경량화 기기, SW 경량화 환경에서 효율이 떨어지는 단점을 보완하고  AES 알고리즘과의 경량/경쟁 호환성을 위해 개발되었다
- 주요 특징
블록 크기 : 128비트
키 길이 : 128, 192, 256비트 지원
구조 : SPN 구조
장점 : 경량화 환경에 유리하며, 하드웨어 및 소프트웨어 구현 시 비트연산 위주로 동작하여 속도가 빠르고 경량 기기에 적합하다
AES
- 2001년 미국 표준기술연구소가 공모를 통해 지정한 세계적 표준 대칭키 블록 암호 알고리즘이다
- 개발배경 : DES의 키 길이가 짧아 해킹 위험이 높아짐에 따라 전 세계 표준으로 활용할 강력한 암호화 표준의 필요성으로 탄생했다.
- 주요특징
블록 크기 : 128비트
키 길이 : 128비트, 192비트, 256비트
구조 : SPN
장점
- 안정성, 속도, 메모리 효율성이 뛰어나며 현재 전 세계 대부분의 연계보안에서 가장 널리 쓰이는 사실상의 글로벌 표준이다.

암호화 KEY를 관리하는 방식
1. KEY VALUT(키 볼트)
소프트웨어 기반의 클라우드 암호화 키/비밀정보 관리 서비스
보관 대상 : DB 암호화 키 뿐만아니라 API 인증키, 비밀번호, SSL/TLS 증명서 등 다양한 비밀정보를 한 곳에서 관리한다
접근제어 : 어플리케이션이  Key Vault에 접근할 때 정당한 권한이 있는지 확인한 후 키를 제공하거나, Vault 내부에서 직접 암복호화를 수행해준다.

대칭키 : 하나의 암호키로 암호화 복호화를 수행
장점
- 매우 빠르다
- 대용량 데이터에 적합
단점
- 키를 안전하게 전달해야 한다

비대칭키 암호화 : 공개키를 통해 암호화하고 개인키를 통해 복호화 한다

공개키(Public Key)
- 누구나 볼 수 있도록 공개된 키
- 데이터를 암호화 하거나, 전자서명을 검증 할 때 사용
- 인터넷이나 연계 시스템을 통해 누구에게나 자유롭게 배포할 수 있다.
- 공개키로 암호화된 데이터는 오직 그와 짝을 이루는 개인키로만 복호화 할 수 있다
- 공개키가 외부에 노출되어도 해당 키로는 데이터를 복호화 할 수 없기 때문에 안전하다

개인키(Private Key)
- 소유자 본인만 안전하게 보관해야 하는 비밀 키
- 암호화된 데이터를 복호화 하거나, 전자서명을 생성할 때 사용한다.
- 절대로 외부에 유출되어서는 안되며, HSM이나 Key Vault같은 보안 저장소에 안전하게 보관해야 한다.
- 개인키를 분실하거나 유출당하면 암호화된 데이터가 해독되거나 타인이 나를 사칭할 수 있게 된다.
