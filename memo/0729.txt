통합구현
서로 다른 시스템이나 모듈을 연결하여 데이터를 주고받고 하나의 서비스처럼 동작하도록 만드는 과정

통합구현을 해야 하는 이유
- 서로다른 시스템(이기종 시스템)간 데이터 연계 필요성이 증가
ㄴ 우리가 만든 서비스(쇼핑몰,게시판)
ㄴ ERP : 회사의 모든 자원과 업무를 하나의 시스템으로 통합하여 관리하는 시스템
ㄴ CRM : 고객 관계 관리 시스템
ㄴ 모바일로 만든 앱
- 서비스 확장성 및 재사용성 확보
ㄴ 모바일 앱 추가
ㄴ 키오스크가 추가
- 데이터 자동 전달을 통한 운영 효율성 및 데이터 품질 향상
ㄴ 통합구현을 통해 데이터를 자동으로 전달하면 업무 속도가 빨라지고, 오류가 줄어들며,데이터의 정확성이 높아진다.
- 데이터 조합을 통한 신규 서비스 창출
ㄴ 여러 시스템의 데이터를 하나로 모아 새로운 정보를 만들거나 새로운 서비스를 제공할 수 있다.

통합구현의 주요 기능 및 구성 요소
- 데이터 생성 및 송수신 : 송신 시스템에서 연계 규격에 맞게 데이터를 생성하여 전송
- 데이터 변환 및 매핑 : 서로 다른 시스템 간 컬럼명/데이터 구조를 일치시키는 작업
- 데이터 수신 및 정제 : 불필요한 공백/중복 제거, NULL 처리, 날짜 형식 통일 등 수신 데이터 검증
- 연계 데이터 관리 : 데이터 형식(JSON,XML,CSV등) 및 저장 방식(DB, Message Queue 등) 관리
ㄴ Message Queue : 시스템과 시스템 사이에서 주고받는 메시지를 잠시 저장해 두었다가 순서대로 전달하는 방식, 바로 받아서 처리하지는 못하더라도 메시지를 온 순서대로 줄을 세워놓고, 받을 수 있을 때 하나씩 처리하는 구조
- 네트워크 및 프로토콜 관리 : 안전한 통신 규칙 적용(HTTP/HTTPS, FTP, TCP/UDP 등)

연계 요구사항 분석
시스템 연결 전 어떤 데이터를 어떤 방식으로 주고받을 지 분석하는 설계 단계
입력물 : 시스템 구성도, 응용 어플리케이션 구성도, ERD, 테이블 정의서
- 현행 시스템 및 운영 환경 파악 : H/W,S/W,N/W,DB,ERD 확인
- 사용자 요구사항 수집 : 인터뷰, 설문, 체크리스트,FGI, 델파이 기법
- 연계 데이터 분석 : 데이터 형식, 변환, 보안 및 연계 솔루션 검토
- 결과 정리 : 요구사항 분석서, 인터페이스 정의서, 회의록 작성

연계 데이터 식별 및 표준화
- 서로 다른 시스템 간 데이터를 주고받기 위해 연계 대상을 정확히 찾아내고, 동일한 기준(규격)으로 정의하는 작업
- 연계 설계의 기초 단계이며, 인터페이스 정의서 작성 및 연계 프로그램 개발의 기준
- 시스템마다 동일한 정보를 관리하더라도 컬럼명, 데이터 길이, 코드 체계 등이 다르므로 사전에 일치시키는 작업이 필요하다

연계 데이터 식별 절차
1. 송/수신 데이터 식별
- DB의 테이블 정의서 및 코드 정의서를 분석하여 연계에 필요한 컬럼과 데이터를 추출
- 컬럼명, 데이터 타입, 데이터 길이, PK 여부, NULL 허용 여부 등을 확인
2. 연계 데이터 형식 정의
- 송/수신 시스템 환경 및 연계 솔루션 특성에 맞춰 데이터 전송 형식 선정
- JSON : 가장 표준적으로 널리 사용됨(가볍고 가독성 좋음)
- XML : 공공기관이나 레거시 시스템 연계시 주로 활용
- CSV/TEXT : 대용량 파일 연계 또는 단순 데이터 전송시 활용
3. 코드 체계 매핑
- 송/수신 시스템 간 공통 코드 체계가 다를 경우 변환 규칙 정의

데이터 표준화 시 주요 점검 사항
1. 컬럼명 및 데이터 구조 매핑 : 서로 다른 항목명을 1대1ㄹ로 매핑하여 일치시킨다 (name vs userName)
2. 데이터 타입 및 길이 정합성 검토 : 송신측 길이가 수신측 보다 긴 경우 데이터 손실 위험이 발생하므로 사전 조정 필요
3. 데이터 정제 기준 마련 : 수신한 데이터 저장 전 공백 제거, 중복 제거, NULL 처리, 날짜/전화번호 형식 통일 등의 정제 규칙 적용

연계 메커니즘 구성하기
- 어플리케이션과 외부 연계 대상 모듈 간 데이터 송수신 요구사항을 충족하고, 데이터 형식, 전송 방식, 보안, 신뢰성을 고려하여 데이터를 안정적으로 교환하는 기술적 체계 및 프로세스

주요 구성 요소
1. 송신 시스템 : 연계 데이터를 생성하고 전달
2. 수신 시스템 : 연계 데이터를 받아서 운영 DB에 반영
3. 인터페이스 테이블 또는 파일 : 데이터를 임시로 저장하는 중간 영역
4. 연계 서버 또는 어댑터 : 시스템 간 중계자 역할 수행
5. 로깅 및 모니터 : 처리 이력 기록 및 상태 관제

연계 데이터 생성 및 추출
- 운영 DB/어플리케이션에서 필요한 데이터를 선별,가공하여 전송용 데이터로 만드는 작업
- 핵심 고려사항
ㄴ데이터 품질 : 누락/오류 방지
ㄴ성능 최적화 : DB 부하 축소를 위한 배치 주기, 추출 범위 및 조건을 적절히 설계
ㄴ운영 안정성 : 로깅, 오류 처리, 중복 전송 방지 및 재처리

코드 매핑 & 데이터 변환
- 송신측 데이터(코드,타입,포맷)를 수신측 표준 규격에 맞추어 변환하는 작업
- 데이터 정합성 및 상호 운용성 확보
- 표준 코드 체계 : ISO, UN/EDIFACT, HL7등 외부/공공 표준 준수 필요

연계 서버 및 어댑터
- 송/수신 시스템 사이에서, 데이터 포맷, 통신 프로토콜, 보안 정책의 차이를 완화해주는 미들웨어/엔진
주요기능
데이터/프로토콜 변환 : JSON -> XML, REST -> FTP 변환
메시지 라우팅 : 목적지 시스템 지정 전송
보안 제어 : 데이터 암/복호화, 인증/인가, 접근 제어
오류 관리 & 재처리 : 전송 실패 시 실패 데이터만 재전송

로그 기록 및 운영 DB에 반영
로그 활용 : 장애 원인 분석, 모니터링, SLA 준수 검증, 감사 및 규제 대응, 실패 건 재처리 구분
운영DB 반영 절차
1. 수신 데이터를 I/F 테이블이나 파일에 저장
2. 데이터 정합성/ 무결성 및 업무 규칙 검증
3. 변경 구분(Insert, Update, Delete)에 맞춰 최종 운영 DB테이블에 반영
4. 트랜잭션 처리

CDC(Change Data Capture 변경 데이터 포착)
- 송신 시스템 DB에서 데이터가 생성,수정,삭제되는 등 변경된 부분만을 실시간으로 감지하여 추출하는 기술/프로그램
- 전체 데이터를 매번 수집하는 방식에 비해 시스템 부하가 적고, 실시간 데이터 연계 및 동기화에 유용하다.

Data Warehouse
- 여러 데이터베이스나 운영 시스템으로부터 데이터를 추출, 변환, 적재하여 한곳에 모아둔 분석 전용 대용량 데이터베이스 저장소

ELK : 대용량 로그 수집,분석, 검색에 특화된 오픈소스 기반의 데이터 관리기술입니다.
Grafana: 시각화 및 데이터 분석 대시보드에 최적화된 오픈소스 플랫폼
AWS cloud watch : AWS 환경에서 제공되는 일체형 관리형 모니터링 서비스

kafka : 고성능 분산 이벤트 스트리밍 플랫폼
메시지(데이터)를 받으면 메모리 뿐만 아니라 디스크에 순차적으로 저장 및 보관하여 높은 데이터 신뢰성을 제공한다

Pulsar : 차세대 분산 메시징 및 스트리밍 플랫폼

QoS(Quailty of Service, 서비스 품질)
- 네트워크가 시스템에서 중요한 트래픽(데이터)에 우선순위를 부여하여, 한정된 자원 속에서도 특정 서비스의 성능과 신뢰성을 보장하는 기술 및 통제 메커니즘

Avro: 데이터를 가로 방향으로 차곡차곡 모아서 저장하는 포맷
Parquet : 데이터를 세로 방향으로 그룹화하여 저장하는 포맷

연계기술
실시간 API : 필요할 때 즉각적인 답을 주고받는 1:1 대화
클라이언트가 서버에 데이터를 요청하면, 중간 매개체 없이 즉시 처리 결과를 응답해 주는 방식
메시지 큐 : 작업을 차곡차곡 쌓아두는 1:1 번호표 창구
데이터를 송신자가 대기열에 넣으면, 수신자가 하나씩 꺼내서 처리하는 방식
이벤트 스트리밍 : 시스템에서 발생하는 모든 변화를 연속적인 데이터 흐름으로 다루며, 이를 실시간으로 수집, 저장, 분석하는 기술
Pub/Sub : 메시지를 보내는 쪽(Publisher)은 특정 주제에 메시지를 내보내고, 해당 주제를 구독(Subscribe)하고 있는 여러 수신자에게 동시에 메시지가 전달되는 방식

연계 표준 최신 기술 동향
오픈 API : 기업이나 기관이 내부 시스템의 데이터나 기능을 외부 개발자가 자유롭게 활동할 수 있도록 공개한 인터페이스

Restful API : REST아키텍처 스타일을 따르는 API

GraphQL : Meta가 개발한 쿼리 언어, REST API의 단점을 보완하기 위해 등장했다.

REST API의 단점
설계 표준의 한계 : 공식적이고 강제적은 표쥰 규약이 없어 설계하는 사람마다 방식이 다를 수 있다.
데이터 전송의 비효율성
- 클라이언트가 필요로 하지 않는 불필요한 데이터까지 서버가 응답으로 보낼 수 있다
- 필요한 데이터를 한 번에 가져오지 못해 여러 번의 API 요청을 보내야 한다.
구조적 제약 : 서버가 이전 요청 상태를 기억하지 않아 매번 인증 등의 추가 정보를 보내야 하므로 통신량이 늘어날 수 있다.
- GET,POST,PUT,DELETE같은 제한적인 메서드만 사용하므로 복잡한 연산을 표현하기 까다롭다

AsyncAPI : REST API 명세에서 사용하는 OpenAPI 명세를 비동기/메시징 아키텍처(kafka)로 확장한 표준 명세서

ISO 20022 : ISO가 제정한 금융 메시지 교환 표준 규격
- XML, JSON 기반으로 표준화되어 세계 각국의 은행, 증권, 결제망에서 데이터 손실 없이 메시지를 주고받도록한다.

Kong : 경량화와 뛰어난 성능을 잘하는 대표적인 클라우드 네이티브 API GateWay

Apigee : 구글 클라우드가 제공하는 대규모 기업용 풀스택 API 관리 플랫폼
- API 설계, 시뮬레이션, 테스트, 보안, 모니터링, 수익화까지 전체 생명주기를 관리

NGINX : 트래픽이 몰리는 대용량 환경을 처리하기 위해 만들어진 고성능 웹 서버

WSO2 : 오픈소스 기반의 통합 API / Identity(식별,인증,인가) / 연계 미들웨어 플랫폼

OAuth2 : 사용자가 비밀번호를 입력하거나 노출하지 않고도, 제3자 어플리케이션이 사용자의 데이터에 안전하게 접근할 수 있도록 권한을 위임하는 표준 프레임워크

소셜로그인의 기반이 되는 기술이다

4가지 구성요소
Resource Owner : 사용자나 데이터의 주인
Client : 사용자의 데이터에 접근하려는 신규 앱/웹 서비스
Authorization Server : 사용자를 인증하고 Access Token을 발급해 주는 인증 담당 서버
Resource Server : 사용자의 실제 데이터를 보관하고 있는 데이터 서버

ETL(Extract Transform Load 추출 변환 적재)
원천 시스템에서 데이터를 가져와서 데이터 정제,규격 통일, 암호화, 가공 처리를 수행하고 변환 완료된 데이터를 최종 분석 시스템에 적재한다.

ELT(Extract Load Transform 추출 적재 변환)
원천 시스템에서 데이터를 가져와 변환과정 없이 원본 데이터를 그대로 대용량 클라우드 저장소에 적재한다.
데이터가 적재된 고성능 클라우드 분석 엔진을 활용해 필요할 때 추출/분석하며 변환한다.

연계 메커니즘 정의하기

1. 구성요소 파악
- 연계 메커니즘을 정의하기 위해 송/수신 시스템의 세부 기능과 중간 처리 장치들을 식별하는 단계

송신시스템의 세부구성
데이터 추출 프로그램 : SQL, Batch, CDC등을 통해 연계 대상 데이터 생성
로그 관리 : 데이터 추출 및 전송의 성공/실패 이력 기록
에러 처리 로직 : 전송 실패 시 재처리 및 예외 상황 대응

수신시스템의 세부구성
데이터 변환 로직 : 수신한 데이의 코드 매핑 및 데이터 타입 변환
적재 프로그램 : 운영 DB에 Insert, Update, Delete 수행
에러 및 재처리 로직 : 적재/변환 실패 시 해당 데이터 별도 관리 및 재처리
운영 DB Table : 최종 연계 데이터를 보관하는 수신 측 실제 업무 테이블

2. 연계 서버 및 연계 방식 정의
연계 서버의 역할 : 송/수신 시스템 간 중계자로, 이기종간 포맷, 프로토콜, 변환및 보안 관리
연계 방식 선택 기준 :
- 실시간 처리 : REST API, Socket, Eventn-Driven
- 대용량/비 실시간 처리 : 배치 파일 전송(FTP), DB Link/Connection

3. 인터페이스 테이블 및 임시 영역 정의
- 시스템간 스키마 전송 주기 차이를 완화하기 위해 임시 보관 가공 검증하는 영역

4. 로깅 및 장애 복구 계획 정의
로그 관리 목적 : 송수신 모니터링, SLA수준확인, 감사 대응 , 장애 발생시 문제 추적성 확보
재처리 매커니즘 : 데이터 전송/삭제 실패 시 실패한 건만 선발하여 다시 전송할 수 있는 채러기 관리 체계  구축

1. 운영 DB의 트랜잭션 로그를 실시간으로 감지하여, 전체 데이터를 조회하지 않고 변경된 데이터만 선별적으로 추출하는 기술

2. 서로 다른 서비스 및 시스템 간 API 호출을 단일 엔드포인트로 통합하여 중계하는 미들웨어/플랫폼이다
주요기능
- 트래픽 및 보안 관리 : OAuth2, JWT 등을 통한 인증/인가 및 접근 제어
- 메시지/프로토콜 변환 : JSON -> XML로 변환, REST -> gRPC

3. 송/수신 시스템 사이에서 데이터를 직접 반영하지 않고 임시로 보관하기 위해 사용하는 중간 DB 테이블이다.
주요 목적
- 시스템 간 차이 완화 : 송수신 시스템의 스키마, 데이터 포맷, 전송 주기의 차이를 해소한다.
- 트랜잭션 및 오류 관리 : 데이터 전송 및 적재 중 오류 발생 시, 해당 데이터를 확인하고 실패건만 선택적으로 재처리 할 수 있도록 지원한다

4. 송수신 시스템 간 데이터 연계 과정에서 발생한 모든 처리 이력과 결과를 시간 순으로 기록해둔 데이터
기록되어야 하는 주요 항목 3가지
1. 송수신 일시
2. 인터페이스 ID 또는 테이블/파일명
3. 처리 단계 및 결과 상태
4. 처리 건수
5. 오류 코드 및 에러 메시지

노드의 장애 요인
자원 고갈 : CPU, 메모리(RAM), Disk 용량 부족으로 인한 서버 다운
하드웨어/인프라 장애 : 클라우드 제공업체의 데이터센터 물리 서버 고장
OS 및 커널 오류 : OS의 멈춤 현상 또는 OS 패치 작업 중 오류

컨테이너의 장애요인
메모리초과 : 설정된 메모리 제한을 초과하여 OS에 의해 컨테이너 프로세스가 강제로 종료되는 현상
컨테이너 크래시 : 내부 어플리케이션 버그나 환경 변수 설정미비로 컨테이너가 계속해서 재부팅되는 현상
이미지 오류 : 컨테이너 실행에 필요한 어플리케이션 파일이나 라이브러리가 누락된 경우

API 장애 요인
타임아웃및 지연 : 요청을 보냈으나 상대방 API의 응답이 너무 늦어 연결이 끊기는 현상
인증/인가 실패 : API Key의 만료, JWT 토큰 오류, Zero Trust 보안 정책으로 인한 접근 거부
규격 및 스키마 불일치 : API 요청/응답 데이터의 필드명이나 데이터 타입이 달라 파싱에 실패하는 문제

네트워크장애요인
네트워크 병목 및 패킷 손실 : 트래픽 급증으로 통신 데이터가 유실되거나 전송 속도가 극도로 느려지는 현상
DNS 확인 실패 : 도메인 주소를 IP주소로 변환하지 못해 서버를 찾지 못하는 문제
라우팅 및 방화벽 설정 오류 : Security Group, Network ACL, VPC 라우팅 테이블이 잘못 설정되어 통신이 차단되는 문제

MSA의 장애추적이 어려움
한 번의 사용자 요청을 처리하기 위해 여러 마이크로서비스 간에 API 호출이 연쇄적으로 일어난다. 따라서 중간에 특정 서비스 하나가 멈추거나 지연되면 어디서 병목이나 오류가 발생했는지 찾기 어렵다
요청이 들어올 때 고유한 Trace ID를 발급하여 서비스 전체 경로를 추적해야 한다

연계 오류 처리 방안 구현
송/수신 시스템, 연계 서버, 파일, I/F테이블 등에서 데이터를 주고받는 과정에서 데이터가 정상적으로 전송 수신 저장 처리되지 못해 발생하는 문제

연계 오류 유형
연계 시스템 오류 : 네트워크 연결 끊김, 서버가 멈춤, 디렉터리/파일의 부재
연계 프로그램 오류 :데이터 변환 로직 오류, 매핑 프로그램 버그
연계 데이터 오류 : 필수값 누락, 데이터 타입 불일치, 중복 데이터 입력

장애 및 오류 로그
장애 발생 시점, 이유, 유형, 대상 데이터를 시간순으로 추적할 수 있도록 기록해둔 흔적

핵심역할
오류 식별 : 근본 원인을 규명
해결 시간 단축 : 신속한 장애 조치 가능
데이터 신뢰성 확보 : 영향 범위를 명확히 파악하여 데이터 정합성 유지
시스템 안정성 확보 : 장애 패턴 추적을 통한 사전 예방
감사 및 규제 대응 : 법적 증거 자료로 활용

장애 및 오류 분석 절차
1차 확인 : 모니터링 대시보드를 통해 장애 여부, 알람, 트렌드 확인
2차 심층 분석 : Trace ID, CorrelationID기준 심층 조회
장애코드 분류 : 장애 유형/소스를 분리하고 오류 코드와 메시지 매핑
장애 원인 분석 : 근본 원인분석(RCA)및 머신러닝 기반 패턴 탐색
대응 및 재처리 결정 : 수작업 재처리 VS 자동 복구 방식
이력 기록 및 리포트 작성 : CI/CD 및 KPI 지표 관리와 연계하여 지속적 개선

기록 단위 기준 오류 로그의 유형
시스템 로그 : 연계 서버 자체의 실행 접속 전송 상태 등 전반적 기록
연계 로그 : 송수신 데이터 단위의 전송,변환, 처리 등 오류 기록
데이터 로그 : 개별 행, 데이터 필드 단위의 상세 오류 기록
